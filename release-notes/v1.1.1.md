## v1.1.1

A bug-fix release. The DHCP fix comes from [#29](https://github.com/johnnyh1975/ha_sophos_fw/issues/29) (thanks @ZorkaTheDog); the other changes come from an audit of every request against real SFOS data (Sophos API documentation, Sophos' SDK, Ansible collection and migration utility, recorded firewall responses).

### Changes that can affect automations

- **The "Trigger backup" button is removed.** It wrote the backup schedule back with only mode and frequency: no source shows that this starts a backup, the mandatory fields (e-mail address, time) were missing, and without a readable schedule it wrote frequency "Never", which switched scheduled backups off. The XML API documents no way to start a backup now. The entity is removed on the first start.
- **DHCP sensor attributes:** `lease_range` (always empty) is replaced by `default_lease_time` and `max_lease_time` in minutes. `leases` and `lease_count` now hold the real static leases.

### Fixed

- **Static DHCP leases** showed `lease_count: 1` and `leases: [{}]` no matter how many mappings a server had. SFOS wraps every mapping in its own `<Lease>` element; the parser expected the fields one level higher. The lease time was read from a field that does not exist; SFOS reports `DefaultLeaseTime` and `MaxLeaseTime`.
- **Firewall rule and web filter switches** sent only the name and the new value. SFOS replaces the object on an update and documents fields such as the rule position as mandatory. A switch now reads the rule or policy, changes only that one value and writes the whole object back.
- **A write without a confirmation** from the firewall counted as success; it is now an error with the firewall's message.
- **An empty answer** ("Number of records Zero") was treated as a record.

### Under the hood

- Diagnostics show the number and field names of the static DHCP leases (still without MAC, IP or hostname), so a wrong shape is visible.
- The test fakes now answer like a real SFOS: real XML structures and SNMP types and values from a field firewall; an update with missing mandatory fields is rejected like on SFOS.

### Known limitations

- The interface sensor shows whether a port is switched on in the firewall, not whether a cable is connected. The real link state is in a field whose values are not documented; it will follow once real data is available.
- IPv6 DHCP servers are not read.
