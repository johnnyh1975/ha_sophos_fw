## v1.2.0

Real link state for interfaces, actions to block sites and devices, new sensors and switches for wireless, access points, PoE and IPsec — and fixes for DHCP and for how switches write to the firewall. The DHCP fix comes from [#29](https://github.com/johnnyh1975/ha_sophos_fw/issues/29) (thanks @ZorkaTheDog). Everything else comes from an audit of every request against real SFOS data: Sophos API documentation, Sophos' SDK, Ansible collection and migration utility, recorded firewall responses and the MIB. There was no v1.1.1.

Parts marked ⚗️ are built from that documentation but **not tested on a real firewall** (no appliance with access points, PoE or IPsec was available). Entities only appear when the firewall reports data. Feedback in an issue is very welcome.

### Changes that can affect automations

- **Interface sensors show the real link with SNMP.** Until now "Connected" meant "the port is switched on in the firewall" (the XML API's InterfaceStatus is the on/off switch). With SNMP the sensor now uses the interface's link state (IF-MIB `ifOperStatus`): a port without a cable or link is "Disconnected". If the SNMP agent does not answer, the sensor is *unknown* instead of falling back to the on/off switch. Without SNMP nothing changes. New attributes: `enabled` (switched on), `link_source` (`snmp`/`switch`), `oper_status`.
- **The "Trigger backup" button is removed.** It wrote the backup schedule back with only mode and frequency: no source shows that this starts a backup, the mandatory fields (e-mail address, time) were missing, and without a readable schedule it wrote frequency "Never", which switched scheduled backups off. The XML API documents no way to start a backup now. The entity is removed on the first start.
- **DHCP sensor attributes:** `lease_range` (always empty) is replaced by `default_lease_time` and `max_lease_time` in minutes. `leases` and `lease_count` now hold the real static leases; `leases` is no longer stored in the recorder (it contains every MAC address).
- **Switching a rule or web filter policy takes longer** (roughly 15–30 s): the whole object is read, changed and written back, then re-read; each XML request takes 5–10 s.

### New

- **Actions** `sophos_firewall.block_url` / `unblock_url`: add or remove a domain in a web filter URL group you block in a web policy. `sophos_firewall.block_device` / `unblock_device`: add or remove a device (IPv4) in an IP host group you use as the source of a drop rule; the IP host is reused or created. Built-in groups are refused. They need "Allow changes" and return `changed`.
- **Wireless networks** ⚗️ (option *Wireless networks*, off by default): on/off as a switch with write access, otherwise as a sensor — e.g. a guest Wi-Fi switch.
- **Access points** ⚗️ (SNMP): connected to the firewall, and the number of clients.
- **PoE power per port** ⚗️ (SNMP), in W.
- **IPsec switch** ⚗️ with write access: activate/deactivate a connection (state from SNMP, written through the XML API).

### Fixed

- **Static DHCP leases** showed `lease_count: 1` and `leases: [{}]` no matter how many mappings a server had. SFOS wraps every mapping in its own `<Lease>` element; the parser expected the fields one level higher. The lease time was read from a field that does not exist; SFOS reports `DefaultLeaseTime` and `MaxLeaseTime`.
- **Firewall rule and web filter switches** sent only the name and the new value. SFOS replaces the object on an update and documents fields such as the rule position as mandatory. A switch now reads the rule or policy, changes only that one value and writes the whole object back, with no other request in between.
- **A write without a confirmation** from the firewall counted as success; it is now an error (with the firewall's message and the rejected fields, when it sends them).

### Under the hood

- An empty answer ("Number of records Zero") is no longer handled like a record (no visible effect before).
- Diagnostics show the number and field names of the static DHCP leases (still without MAC, IP or hostname), so a wrong shape is visible.
- The test fakes now answer like a real SFOS: real XML structures and SNMP types and values from a field firewall; an update with missing mandatory fields is rejected like on SFOS.
- `.gitignore` restored.

### Known limitations

- Without SNMP the interface sensor can only show whether a port is switched on.
- IPv6 DHCP servers are not read; the device actions accept IPv4 only.
- ⚗️ Not verified: whether the IPsec connection name in the SNMP tunnel table equals the name in the XML API (otherwise switching fails with an error), and what a firewall without wireless answers to the wireless query.
