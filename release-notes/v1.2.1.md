## v1.2.1

A small release: switches report back sooner, and the HACS package contains only the repository's files.

### Fixed

- **Switches report back as soon as the firewall confirms the write** ([#40](https://github.com/johnnyh1975/ha_sophos_fw/issues/40), thanks @jayscovill). Since 1.2.0 a switch reads the object, writes it back whole and then re-reads it, and the action waited for all three XML requests. Each request takes several seconds (5–10 s on the firewalls I have logs from), while the Apple Watch gives an action 15 s, so toggling from the Watch showed "didn't report back in time" although the switch had changed. The re-read now runs in the background; the switch shows the new state right away and the firewall's state once the re-read is done. A failed write is still reported as an error at once.
- **No Python bytecode in `sophos_firewall.zip`.** The release workflow ran the tests before packaging, and the tests left `__pycache__/*.pyc` files that ended up in the zip. Tests now run without writing bytecode, the zip excludes it, and the release fails if a `.pyc` file still gets in. (Reported in the HACS default review.)

### Under the hood

- README: install from the HACS search first; adding the repository by hand is the fallback.
