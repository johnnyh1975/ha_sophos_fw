## v1.0.2

A large maintenance and hardening release: new entities requested by the community, a full architecture/code review with the resulting bug fixes, a robustness-hardening pass, and a concurrency review. The test suite grew from ~120 to 164 and now runs with no deselects.

### New entities

- **High Availability cluster** (requested by @adi-debug99): cluster status (active/inactive) plus the role of this node and its peer (primary / auxiliary / standalone / faulty / ready / not-applicable), all localised.
- **Power supply status** (`SophosPSUSensor`) for physical appliances — one binary sensor per PSU. No effect on virtual appliances (SFVH), which report no PSUs.
- **IMAP and POP3 connection sensors**, alongside the existing HTTP/SMTP/FTP hit counters.

### Bug fixes (from code review)

- `trigger_backup()` now checks the response status — a backup the firewall rejects (e.g. mail backup with no mail server configured) surfaces as a visible error instead of a silent success.
- `RestoreEntity` is now actually implemented on the interface/VPN sensors and both switches — they show their last known state immediately after a restart instead of going `unavailable`.
- Response-level Status codes **532** (API not enabled), **534** (IP not in access list) and **535** (auth/authz) are now detected instead of slipping through as an empty response. Verified against Sophos' own API behaviour.
- Switches now apply **optimistic state** (instant UI feedback) and revert on write failure, raising a clear error.
- `_get_tag` skips an individual malformed record instead of discarding the whole list.
- Removed dead code and unused imports.

### Hardening

- Central `field_str()` helper guards every XML field read — a `None` or unexpectedly nested value can no longer crash an entity's state property and take down a platform.
- Robust OID parsing in the health fetch — a malformed OID is skipped, not fatal.
- HTTP session close is now exception-tolerant, so a failed close can never block config-entry unload.
- The coordinator clamps an invalid (zero/negative/non-integer) poll interval to the default, preventing a busy-loop that would hammer the firewall.
- A thread lock serialises the one-time puresnmp plugin patch across concurrent multi-firewall setup.

### Tests

- Grown from ~120 to **164 tests**; the full suite runs with no deselects.
- Every fix and hardening change ships with a regression test, several proven to fail without the fix.

### Quality Scale

Bronze, Silver and Gold remain fully met. The one open Platinum rule is `async-dependency` (puresnmp uses a blocking import, worked around via executor preload).
