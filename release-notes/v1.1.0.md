## v1.1.0

A large release: new sensors (CPU, interface traffic, every service and license), repair issues, a rebuilt data layer that never shows made-up values, stable entity IDs, and a much faster startup. **Please read "Changes that can affect automations" before updating.**

Requires **Home Assistant 2025.5** or newer.

### Changes that can affect automations

- **Uptime is now "Last boot"**, a timestamp (shown as "3 days ago"). The entity ID stays `sensor.<firewall>_sensor_uptime`; the text state ("75 d 6 h") and the `uptime_seconds` attribute are gone. The state only changes when the firewall reboots, instead of every 30 s.
- **Web filter default action** states are now `allow` / `deny` (shown translated, e.g. "Allow"/"Zulassen"); before: `Allow` / `Deny`. **Backup frequency** states are `never` / `daily` / `weekly` / `monthly`; before: `Monthly` etc.
- **Services and licenses summaries** no longer carry the pseudo-units "/ 21 running" and "/ 9 OK". The total is the new `total` attribute. Home Assistant reports once that the unit of these two sensors changed; confirm it under *Developer tools → Statistics*, until then their long-term statistics pause. The display names of six services/licenses in the attributes are now English ("Base Firewall", "Web Protection", "Email Protection", "Zero-Day Protection", "Database", "Network"). Both sensors show *unknown* instead of `0` when the firewall reports no state at all.
- **No restored states after a restart.** Interface, VPN and switch entities no longer show their last known state after a Home Assistant restart; they are *unavailable* until their first successful poll: a few seconds for VPN (SNMP), up to about 35 s for interfaces, rules and web filters (XML API). Automations that trigger on a change from *unavailable* to on/off may fire at startup.
- **SNMP failures make the SNMP entities unavailable.** 1.0.x showed plausible values instead (0 % RAM, "0 / 21 running", hit counters dropping to 0, which Home Assistant counted as a reset and then added the whole counter again).
- **The SNMP version setting is gone.** The integration speaks SNMP v2c; the old "1" option was never used anyway.
- **German names:** firewall rule entities are called "Regel …" (was the untranslated "Rule …"). With an English UI all entity names are English again (v1.0.2's English translation lacked most of them, see *Fixed*).

### After updating

Everything below happens automatically on the first start:

- **Entity IDs are kept.** The internal unique IDs move from host and port to the config entry ID, so a new IP address or port no longer creates a second set of entities. Names, areas, disabled flags and history are kept. Entities orphaned by the 1.0.x reconfigure flow (after a host change) are restored where possible, the rest removed. The config entry moves to version 2: going back to 1.0.x requires restoring a Home Assistant backup.
- **Settings move to the options** (*Configure*); only host, port, credentials and TLS verification stay connection settings (*Reconfigure*).
- **Leftover VPN entities** that 1.0.x created from the IPsec *policy* table (#18) are removed: on firewalls without IPsec connections after three consecutive empty reads, otherwise right away.
- A **web category version** entity is removed when the firmware reports no version (SFOS 22 answers "not available").
- **Entity categories** are updated. New "disabled by default" settings only apply to newly created entities; your existing entities stay enabled.

### New

- **CPU usage** (average of all cores) and one sensor per core (disabled by default), from HOST-RESOURCES-MIB.
- **Interface traffic**: received and sent in Mbit/s per interface, and the transferred totals in GB (disabled by default), from IF-MIB with 64-bit counters, every 30 s. Rates are on by default for the interfaces the XML API lists (the ports); VLANs, wireless networks and tunnel interfaces are created disabled; internal helper devices (lo, dummy0, ipsec0, sit0, gre0, ifb0, dfq, spq, …) get no entities. New option *Interface traffic (SNMP)*.
- **Every service and every license as its own sensor** (disabled by default): service state (running, stopped, unregistered, …), license status and expiry date.
- **Repair issues** in *Settings → Repairs*: "API access denied" (status 532/534, with the fix) and "SNMP agent not answering" (no answer for 10 minutes since the start; a warning, SNMP is optional). Both disappear on their own once fixed, and when the integration is disabled or deleted.
- **Reconfigure** host, port and credentials without losing entities; an address already used by another entry is refused.
- **Icons for every entity**, state-dependent where it helps (interface down, rule off, web filter deny, …). IMAP and POP3 had no icon in 1.0.x.
- **Entity categories and sensible defaults**: versions, temperatures, fans, PSUs, last boot and the per-service/per-license sensors are diagnostic; rarely used entities start disabled.
- **Descriptions** for every field of the setup and options dialogs, in English and German.
- **Diagnostics** show the state of every data source; credentials, community, host, serial number and static DHCP leases are redacted.
- **Debug log** with the wait and response time of every XML request and the duration of each setup step.

### Fixed

- **VPN tunnel sensors never showed the real tunnel state** ([#18](https://github.com/johnnyh1975/ha_sophos_fw/issues/18), thanks @Snaker-L): the IPsec *policy* table was read instead of the tunnel table. All OIDs were re-checked against SFOS-FIREWALL-MIB.
- **Entity names regressed to generic labels in v1.0.2** (23 lost translations); restored, with a test against every translation key used in the code.
- **Startup took 34 s and the admin settings timed out.** The firewall answers XML requests one after another (5–10 s each, measured); with two in flight, the second waited on the firewall while its 20 s timeout ran. Now one request at a time, and setup only waits for the admin settings: about 10 s, the rest loads right after in the background.
- **A single failing XML request made every entity unavailable**, SNMP ones included; now only the entities fed by the failed request.
- **The realtime tier often ran every 60 s instead of 30 s**, and after a Home Assistant host reboot firewall rules, DHCP, web filter and licenses could stay empty for up to 10 or 30 minutes.
- **The web filter switch flipped back** for up to 30 minutes after switching; the written object is now re-read right after the write. A switch used while an update was running could also show its old state for up to 10 minutes (web filter: 30).
- **A dead SNMP agent blocked setup for minutes**, and a walk that failed half-way removed entities. SNMP now has a time budget per request, reads tables per column, and a failed walk never counts as empty.
- **A hardware appliance could be detected as virtual** after one SNMP timeout at startup, which stopped health polling until the next restart. Now only three successful answers without any hardware values in a row mean "virtual", so a firewall that is still booting keeps its fan, PSU and temperature monitoring.
- **Firewall rule action** was empty for rules that keep it inside the policy block.
- **Placeholder texts** such as "not available" were shown as values; they are *unknown* now.
- **SNMP timeouts at startup** from too many simultaneous requests.
- **Setup leaked an HTTP session** on every failed attempt (now also closed when Home Assistant stops), and rejected credentials at startup never started the reauthentication.
- **Switch and button errors** (timeouts, rejected credentials) showed raw exceptions instead of a translated message.
- **Reconfigure orphaned all entities** after a host or port change.
- **Reauthentication and reconfigure reloaded the integration twice** (Home Assistant 2026.8 warns about this; it is announced to stop working in 2026.12). Now once; renaming the entry no longer reloads it at all.
- **Entities of a switched-off data source** stayed "unknown" forever; they are removed now (also when SNMP is switched off as a whole) and come back when the source is switched on again.
- **Hardware entities** (fans, PSUs) were removed when a single reading was missing, so a failed fan could not trigger an alert.
- **Diagnostics leaked** the serial number and the static DHCP leases.
- **The options dialog** saved into two places and reloaded twice.

### Under the hood

- Two coordinators (XML API, SNMP) on a declarative endpoint table with per-endpoint availability; typed dataclass models.
- XML: dedicated HTTP session that never reuses a connection, one request at a time.
- SNMP (puresnmp 2.0.1): own UDP transport that always closes its socket, per-column GETBULK walks (puresnmp truncates multi-column walks), cancellation of sibling walks on failure.
- Tests: 250+ with Home Assistant's test harness, a real UDP SNMP agent and a stateful fake of the XML API; at least 95 % line coverage in every module and `mypy --strict`, both enforced in CI; CI tests Home Assistant 2025.5 and 2026.8.
- Quality scale: all 54 rules assessed in `quality_scale.yaml` (self-assessment: Platinum).
